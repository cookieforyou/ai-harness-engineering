# Testing Scenario

## Purpose

设计和执行测试用例，验证功能正确性，发现并跟踪缺陷，确保软件质量。

## Chain of Thought (思维链)

> AI 执行时的思维引导，帮助逐步完成测试验证工作

### Think-Aloud Protocol

```
THINK: 理解测试范围和策略
   ↓
THINK: 设计测试用例
   ↓
THINK: 准备测试环境
   ↓
THINK: 执行测试用例
   ↓
THINK: 跟踪缺陷修复
   ↓
THINK: 生成测试报告
```

### Step-by-Step Reasoning

**Step 1: 测试策略制定**
- 问：测试策略是否覆盖所有重要场景？
- 验证：功能测试、接口测试、性能测试
- 检查：测试优先级是否合理

**Step 2: 用例设计**
- 问：测试用例是否覆盖所有需求？
- 验证：正向、反向、边界条件
- 检查：用例是否可执行和可重复

**Step 3: 环境准备**
- 问：测试环境是否与生产环境一致？
- 验证：配置、数据、依赖
- 检查：测试数据是否充分

**Step 4: 测试执行**
- 问：所有用例都执行了吗？
- 验证：执行率和通过率
- 检查：缺陷是否正确记录

**Step 5: 缺陷管理**
- 问：缺陷是否都修复并验证了？
- 验证：修复的正确性
- 检查：是否需要回归测试

## Error Handling (错误处理)

### EH-1: 测试环境不可用

- **识别信号**：测试环境无法访问
- **处理方式**：
  1. 检查环境状态
  2. 联系运维人员
  3. 记录问题
  4. 标记为 `[环境阻塞]`
- **升级条件**：影响测试进度

### EH-2: 发现严重缺陷

- **识别信号**：发现 P0/P1 缺陷
- **处理方式**：
  1. 立即记录缺陷
  2. 通知开发负责人
  3. 暂停相关测试
  4. 等待修复后重新测试
- **升级条件**：影响发布决策

### EH-3: 测试用例失败

- **识别信号**：测试用例执行失败
- **处理方式**：
  1. 确认测试环境正确
  2. 验证测试数据正确
  3. 确认为代码问题还是测试问题
  4. 记录并创建缺陷
- **升级条件**：缺陷修复率低

## Expected Output

### 产出清单

1. **测试计划**：测试策略和资源规划
2. **测试用例集**：完整的测试用例
3. **测试报告**：测试执行结果和分析
4. **缺陷报告**：发现的缺陷清单

## Workflow

```
1. 启动 → 理解测试范围
2. 测试计划 → 制定测试策略
3. 用例设计 → 设计测试用例
4. 环境准备 → 搭建测试环境
5. 测试执行 → 执行测试用例
6. 缺陷管理 → 跟踪缺陷
7. 测试报告 → 输出测试报告
8. 完成 → 给出测试结论
```
