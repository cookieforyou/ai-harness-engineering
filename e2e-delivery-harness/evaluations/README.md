# Evaluations

Evaluations 是**质量评估工具**，用于验证资产和交付物是否满足质量标准。

## 概述

评估资产包括：

- **回归检查清单 (Regression Checklists)**：按交付阶段的详细质量检查清单
- **评分卡模板 (Scorecard Templates)**：质量评估的加权评分
- **验证标准 (Validation Criteria)**：资产验证的具体标准

## 回归检查清单 (regression-checklist.md)

按交付阶段组织的综合检查清单：

### 阶段覆盖

| 阶段 | 检查项 | 重点 |
|------|--------|------|
| 1. 需求分析 | R-001 ~ R-015 | 需求完整性、质量 |
| 2. 系统设计 | D-001 ~ D-015 | 架构设计、风险 |
| 3. 任务分解 | T-001 ~ T-015 | 任务粒度、计划 |
| 4. 开发实现 | C-001 ~ C-020 | 代码质量、测试 |
| 5. 测试验证 | E-001 ~ E-020 | 测试覆盖、执行 |
| 6. 部署发布 | P-001 ~ P-020 | 部署准备、执行 |
| 7. 监控运维 | M-001 ~ M-020 | 监控配置、运维 |

### 状态选项

- **PASS**：完全满足要求
- **PARTIAL**：部分满足，需要改进
- **FAIL**：不满足要求，必须修复
- **NA**：不适用

## 评分卡模板 (scorecard-template.md)

用于整体质量评估的加权评分系统：

### 评分结构

| 阶段 | 权重 | 评估标准 |
|------|------|----------|
| 需求分析 | 15% | 完整性、清晰度、可测试性、可追溯性 |
| 系统设计 | 20% | 架构、完整性、安全性、可扩展性 |
| 任务分解 | 10% | 粒度、依赖、估算、计划 |
| 开发实现 | 20% | 代码质量、测试、文档、合规性 |
| 测试验证 | 15% | 计划、覆盖、执行、缺陷管理 |
| 部署发布 | 10% | 就绪、执行、验证、成功率 |
| 监控运维 | 10% | 配置、就绪、响应、健康 |

### 等级标准

| 分数 | 等级 | 描述 |
|------|------|------|
| 90-100 | A | 优秀 - 超出预期 |
| 80-89 | B | 良好 - 满足预期 |
| 70-79 | C | 满意 - 满足基本要求 |
| 60-69 | D | 低于平均 - 需要改进 |
| 0-59 | F | 不及格 - 不满足要求 |

## 使用方式

### 用于阶段门禁

1. 完成相关阶段检查清单项目
2. 记录每个项目的状态 (PASS/PARTIAL/FAIL)
3. 记录任何问题或顾虑
4. 获得质量负责人签字

### 用于发布决策

1. 为每个阶段完成评分卡
2. 计算加权总分
3. 确定等级和状态
4. 记录优势和需要改进的地方
5. 获得所有干系人签字

## 标准格式

每个评估资产应包含：

```yaml
---
name: evaluation-name
type: evaluation
version: "1.0"
scope: [适用阶段]
author: [作者]
created: [ISO日期]
updated: [ISO日期]
---
```
