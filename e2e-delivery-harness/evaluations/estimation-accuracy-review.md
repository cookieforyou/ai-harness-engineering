# 估算准确性回顾 (Estimation Accuracy Review)

## Purpose

本清单用于回顾工作量估算的准确性，通过对比估算值与实际耗时，识别估算偏差模式，持续改进估算能力。适用于迭代回顾和项目阶段复盘。

## Scoring

- **PASS**: 估算准确度达标，偏差模式已分析并制定了改进措施
- **PARTIAL**: 基本达标，但偏差分析不够深入或改进措施不具体
- **FAIL**: 估算与实际情况偏差过大，需系统性地审视估算方法
- **NA**: 不适用（如无估算数据）

## 使用时机

- 每个迭代结束后的回顾环节
- 项目关键里程碑复盘
- 估算流程改进周期（每季度）

## 1. 估算方法评估 (Estimation Method)

- [ ] **EEM-001**: 估算方法已明确记录（如：Planning Poker / T-Shirt Size / 类比估算 / 参数估算 / 三点估算），非随意估计
- [ ] **EEM-002**: 估算基准单位统一（所有人使用相同单位：理想人天/故事点/工时），换算关系清晰
- [ ] **EEM-003**: 估算过程有历史数据支撑（参照类似任务的实际完成时间），非全凭直觉
- [ ] **EEM-004**: 风险缓冲已纳入估算（一般任务 10%、高不确定性任务 20-30%），缓冲使用有跟踪

## 2. 估算 vs 实际分析 (Estimation vs Actual)

- [ ] **EEA-001**: 实际完成时间数据已收集（精确到小时），与估算值一一对应可对比
- [ ] **EEA-002**: 估算准确率 = 1 - |实际值 - 估算值| / 估算值。整体准确率 ≥ 70%（即平均偏差 ≤ 30%）
- [ ] **EEA-003**: 估算偏差分布分析已完成：高估（完成时间小于估算）和低估（完成时间超过估算）的占比
- [ ] **EEA-004**: 单个任务的最大偏差已标识并分析原因（偏差 ≥ 100% 的任务需要特殊说明）
- [ ] **EEA-005**: 估算偏差按任务类型/模块/团队成员分类统计，识别偏差集中领域

## 3. 偏差根因分析 (Bias Analysis)

- [ ] **EBA-001**: 系统性偏差已识别（连续低估或高估超过 3 个迭代），非随机波动
- [ ] **EBA-002**: 低估原因分类：需求变更未反映在估算中、技术复杂度低估、遗漏任务、外部阻塞、其他
- [ ] **EBA-003**: 高估原因分类：过度保守、团队能力提升未反映、复用已有组件、任务范围缩小
- [ ] **EBA-004**: 偏差分析与任务复杂度关联：简单任务（≤ 1 天）偏差 ≤ 25%、中等任务（1-3 天）偏差 ≤ 40%、复杂任务（3-5 天）偏差 ≤ 60%

## 4. 改进跟踪 (Improvement Tracking)

- [ ] **EIT-001**: 上个迭代的估算改进措施已检查执行情况（如：估算中加入测试时间、缓冲比例调整等）
- [ ] **EIT-002**: 估算偏差趋势在改善：最近 3 个迭代的估算准确率呈上升或稳定趋势（或波动不超过 ±10%）
- [ ] **EIT-003**: 估算校准动作已执行：根据历史偏差率调整后续估算的基准值（如：平均低估 20%，则后续估算 × 1.2）
- [ ] **EIT-004**: 新团队成员的估算偏差已单独分析，对新人估算进行导师校准

## 5. 估算偏差示例 (Estimation Bias Examples)

### 常见估算偏差模式

| 偏差模式 | 典型场景 | 影响 | 改进方法 |
|----------|----------|------|----------|
| 乐观偏差 | "这个功能很简单，两天就够了" — 忽略集成和测试时间 | 平均低估 40-60% | 三点估算（乐观/最可能/悲观），取加权平均值 |
| 锚定效应 | 受上一类似任务估算影响，未考虑当前任务复杂度差异 | 偏差方向不可预测 | 独立估算后对比，避免先入为主 |
| 学生综合征 | 非紧迫任务估算偏大，实际在截止日前才完成 | 估算膨胀 30-50% | 拆分为 ≤ 3 天的小任务，每日站会跟踪进度 |
| 范围蔓延 | 实现过程中新增未在估算中反映的功能需求 | 工作量增加 20-50% | 建立变更控制流程，变更必须同步更新估算 |

### 估算校准示例

**场景**: 某团队连续 4 个迭代低估 25%

```
当前公式: 估算 = 初始估算 × (1 + 10% 风险缓冲)
校准公式: 估算 = 初始估算 × (1 + 25% 历史低估率) × (1 + 10% 风险缓冲)
结果: 迭代 5 实际偏差从 -25% 降至 -5%
```

### 不同估算方法准确度对比

| 方法 | 适用阶段 | 典型偏差范围 | 准备工作量 |
|------|----------|-------------|-----------|
| 类比估算 | 项目早期 | ±30-50% | 低（需历史数据） |
| 参数估算（功能点） | 需求明确后 | ±20-30% | 中 |
| 三点估算 | 任务分解后 | ±15-25% | 中 |
| Planning Poker | 迭代计划 | ±10-20% | 低 |
| 专家判断（含 Delphi） | 任何阶段 | ±15-35% | 高（需多名专家） |

### 估算准确性影响因素

| 因素 | 正向影响 | 负向影响 |
|------|----------|----------|
| 需求清晰度 | 需求文档完备，示例明确 | 需求模糊，存在大量 TBD |
| 技术熟悉度 | 团队使用成熟技术栈 ≥ 6 个月 | 引入全新技术栈 |
| 任务粒度 | 任务 ≤ 3 天 | 任务 > 5 天 |
| 人员经验 | 同类任务完成 ≥ 3 次 | 首次执行该类任务 |
