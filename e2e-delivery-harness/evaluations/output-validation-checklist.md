# Output Validation Checklist (输出验证检查清单)

## 概述

本清单用于指导 AI Agent 在完成任何任务输出后执行标准化验证，确保输出质量符合规范要求。

## 验证时机

```
┌─────────────────────────────────────────┐
│  执行 Prompt                            │
│                                         │
│  ↓                                      │
│  生成输出 ──→ 输出验证 ──→ Handover      │
│                  │                      │
│                  ↓                      │
│            [验证通过]?                  │
│           /            \                │
│         是              否              │
│         ↓              ↓                │
│      继续执行      修正输出              │
│                                         │
└─────────────────────────────────────────┘
```

## 通用验证清单

### 1. 完整性检查 (Completeness)

- [ ] **C-001**: 所有必填章节/部分都已填充
- [ ] **C-002**: 关键信息无遗漏
- [ ] **C-003**: 边界情况已考虑
- [ ] **C-004**: 附录/参考资料完整

### 2. 正确性检查 (Correctness)

- [ ] **CR-001**: 信息准确无误
- [ ] **CR-002**: 数据计算正确
- [ ] **CR-003**: 术语使用规范
- [ ] **CR-004**: 与前置阶段无矛盾

### 3. 一致性检查 (Consistency)

- [ ] **CS-001**: 格式统一规范
- [ ] **CS-002**: 命名风格一致
- [ ] **CS-003**: 术语定义一致
- [ ] **CS-004**: 与其他文档交叉引用正确

### 4. 可执行性检查 (Actionability)

- [ ] **A-001**: 每个行动项有明确的 Owner
- [ ] **A-002**: 每个行动项有验收标准
- [ ] **A-003**: 每个行动项有截止日期
- [ ] **A-004**: 行动项可追溯到源头需求

### 5. 可追溯性检查 (Traceability)

- [ ] **T-001**: 输出可追溯到输入需求
- [ ] **T-002**: 决策有明确依据
- [ ] **T-003**: 假设条件已标注
- [ ] **T-004**: 未解决问题已记录

### 6. 清晰度检查 (Clarity)

- [ ] **CL-001**: 结构层次清晰
- [ ] **CL-002**: 关键信息突出
- [ ] **CL-003**: 无歧义描述
- [ ] **CL-004**: 图表辅助说明（如适用）
