# 回滚演练报告评估 (Rollback Drill Report Evaluation)

## Overview

回滚演练报告评估用于系统化评估回滚演练的质量和有效性，确保团队在真实故障发生时能够快速、可靠地将系统恢复到已知正常状态。本评估覆盖演练场景覆盖度、RTO 达成率、问题发现和改进跟踪四个维度，适用于定期安排的回滚演练（至少每季度一次）和重大变更前的回滚预演。

### 适用场景

- 季度回滚演练后的效果评估
- 重大版本发布前的回滚预案验证
- 灾备/高可用架构变更后的恢复能力验证
- 事故复盘中发现回滚问题的根因改进跟踪

---

## Evaluation Criteria

| 维度 | 权重 | 目标值 | 测量方法 |
|------|------|--------|----------|
| 演练场景覆盖度 | 30% | 四类场景覆盖 ≥ 80% | 回滚场景矩阵完成度 |
| RTO 达成率 | 35% | RTO ≤ 15min (P0/P1) | 回滚操作计时 (发现→确认→执行→验证) |
| 问题发现质量 | 15% | P0/P1 问题发现率 ≥ 1次/演练 | 演练中发现的回滚预案缺陷数 |
| 改进措施跟踪 | 20% | 措施关闭率 ≥ 90% (30天内) | 演练改进项追踪表完成率 |

### 回滚场景分类

| 场景类型 | 说明 | 优先级 | RTO 目标 | 演练频率 |
|----------|------|--------|----------|----------|
| 代码回滚 | 应用版本回退至上一稳定版本 | P0 | ≤ 10min | 每季度 |
| 数据库回滚 | Schema 变更回退 / 数据恢复 | P0 | ≤ 15min | 每月 |
| 配置回滚 | 配置中心/环境变量恢复到上一版本 | P1 | ≤ 5min | 每季度 |
| 流量回滚 | 流量调度从新版本切回旧版本 | P0 | ≤ 3min | 每季度 |

---

## Scoring Formula

```
场景覆盖得分 = 已演练场景数 / 总场景数 × 100
RTO得分 = 
  每类场景: RTO_actual ≤ RTO_target → 100
  RTO_actual ≤ RTO_target × 2 → 50
  RTO_actual > RTO_target × 2 → 0
  取四类场景的加权均值

问题发现得分 = min(已发现P0/P1问题数 / 1, 1) × 100  // 至少发现1个P0/P1算满分
改进跟踪得分 = 30天内关闭的改进项 / 总改进项 × 100

总分 = 场景覆盖得分 × 30% + RTO得分 × 35% + 问题发现得分 × 15% + 改进跟踪得分 × 20%
```

### 等级划分

| 等级 | 分数范围 | 判定 |
|------|----------|------|
| S (Excellent) | ≥ 90 | 回滚能力成熟，可应对各类故障 |
| A (Good) | 75-89 | 主要场景覆盖良好，个别项需打磨 |
| B (Fair) | 60-74 | 回滚能力存在明显不足，需强化演练 |
| F (Failed) | < 60 | 回滚能力严重不足，无法保证快速恢复 |

## Checklist

### 1. 演练场景覆盖度检查 (6项)

- [ ] **RBD-SCE-001**: 代码回滚场景已演练，覆盖至少 2 种发布方式（蓝绿/滚动/金丝雀）
- [ ] **RBD-SCE-002**: 数据库回滚场景已演练，包含 DDL 回退和数据修复
- [ ] **RBD-SCE-003**: 配置回滚场景已演练，配置中心回退到上一版本的时间 ≤ 5min
- [ ] **RBD-SCE-004**: 流量切换/路由回滚场景已演练，流量切回旧版本 ≤ 3min
- [ ] **RBD-SCE-005**: 四类场景覆盖度 ≥ 80%，有明确的场景覆盖矩阵图
- [ ] **RBD-SCE-006**: 回滚场景清单随架构变更及时更新（变更后 2 周内）

### 2. RTO 达成率检查 (6项)

- [ ] **RBD-RTO-001**: 代码回滚 RTO ≤ 10min（含构建/部署/验证全流程）
- [ ] **RBD-RTO-002**: 数据库回滚 RTO ≤ 15min（含数据校验一致性检查）
- [ ] **RBD-RTO-003**: 配置回滚 RTO ≤ 5min（配置分发延迟 + 生效时间）
- [ ] **RBD-RTO-004**: 流量回滚 RTO ≤ 3min（DNS/网关/负载均衡配置生效）
- [ ] **RBD-RTO-005**: 回滚计时器在演练中有明确的起止标记（开始回滚决策 → 验证通过）
- [ ] **RBD-RTO-006**: 回滚操作按自动化优先原则（自动化回滚 ≥ 80%，人工命令 ≤ 20%）

### 3. 问题发现分级检查 (5项)

- [ ] **RBD-ISS-001**: P0 (阻塞性) 问题已识别：回滚导致数据不一致、回滚后服务仍不可用
- [ ] **RBD-ISS-002**: P1 (严重) 问题已识别：回滚操作文档缺失、关键依赖未回滚
- [ ] **RBD-ISS-003**: P2 (一般) 问题已识别：回滚验证步骤不完整、回滚耗时超出预期
- [ ] **RBD-ISS-004**: P3 (建议) 问题已记录：回滚脚本可优化、监控告警待补充
- [ ] **RBD-ISS-005**: 问题有严重等级、影响范围分析和明确的修复方案

### 4. 改进措施跟踪检查 (5项)

- [ ] **RBD-FUP-001**: 每项问题有明确的改进措施，指定责任人和截止日期
- [ ] **RBD-FUP-002**: 改进措施关闭率 ≥ 90%（30 天内），逾期措施有升级机制
- [ ] **RBD-FUP-003**: 下次演练前验证改进措施有效性（回测通过率 100%）
- [ ] **RBD-FUP-004**: 改进措施变更日志更新到回滚 Runbook 和应急预案中
- [ ] **RBD-FUP-005**: 改进措施的跟踪表和状态在团队例会中定期回顾（每周/每双周）
