# 回归测试套件评估 (Regression Test Suite Evaluation)

## Overview

回归测试套件评估用于确保回归测试套件的有效性、效率和可靠性。通过分析用例选择策略、优先级分类、执行时间和 Flaky 率，驱动回归测试持续改进。本评估适用于每个迭代结束后的回归测试回顾，以及 CI/CD 流水线中回归测试的质量门禁。

### 适用场景

- 版本发布前的回归测试准入评估
- 回归测试套件健康度定期审计（每月/每迭代）
- 新增功能后回归套件扩编合理性评估
- Flaky 测试治理专项活动

---

## Evaluation Criteria

| 维度 | 权重 | 目标值 | 测量方法 |
|------|------|--------|----------|
| 用例选择策略 | 25% | 变更影响分析覆盖率 ≥ 95% | 追溯矩阵用例 ↔ 代码模块 |
| 优先级分类 | 20% | P0 通过率 100%，P1 ≥ 98% | 回归测试报告分级统计 |
| 执行时间 SLA | 25% | 全量回归 ≤ 30min | CI 流水线执行时间记录 |
| Flaky 率监控 | 30% | Flaky 率 ≤ 3% | 最近 10 次执行结果一致性分析 |

### 优先级定义

| 优先级 | 定义 | 目标通过率 | 执行频率 | 用例占比 |
|--------|------|-----------|----------|----------|
| P0 (核心流程) | 影响核心业务连续性的关键路径 | 100% | 每次 PR/每次发布 | 15-20% |
| P1 (重要功能) | 重要但非关键的业务功能 | ≥ 98% | 每日/每次发布 | 40-50% |
| P2 (边缘场景) | 边界条件、异常路径、非核心功能 | ≥ 95% | 每次发布 | 30-40% |

---

## Scoring Formula

```
策略得分   = 变更影响覆盖率 / 95% × 100（上限 100）
优先级得分 = P0通过率 × 30 + P1通过率 × 20 + P2通过率 × 10 → 归一化至百分制
时间得分   = max(0, 100 - (实际执行分钟 - 15) × 3)        // 15min为靶心, 每超1min扣3分
Flaky得分  = max(0, 100 - Flaky率 × 1000)                 // Flaky率每1%扣10分

总分 = 策略得分 × 25% + 优先级得分 × 20% + 时间得分 × 25% + Flaky得分 × 30%
```

### 等级划分

| 等级 | 分数范围 | 判定 |
|------|----------|------|
| S (Excellent) | ≥ 90 | 回归套件健康可靠 |
| A (Good) | 80-89 | 轻度问题，可发布但需跟踪 |
| B (Fair) | 70-79 | 回归套件存在风险，需修复后发布 |
| F (Failed) | < 70 | 回归套件不可靠，阻塞发布 |

## Checklist

### 1. 用例选择策略检查 (6项)

- [ ] **RGT-SEL-001**: 回归用例选择基于变更影响分析（代码变更 → 影响模块 → 关联测试），非人工凭经验选择
- [ ] **RGT-SEL-002**: 变更影响分析覆盖率 ≥ 95%（变更代码至少被 1 条回归用例覆盖）
- [ ] **RGT-SEL-003**: 回归用例与用户故事/需求有双向追溯矩阵（AC ↔ TC ↔ 代码模块）
- [ ] **RGT-SEL-004**: 新增功能的回归用例在功能合入后 1 个迭代内补充完整
- [ ] **RGT-SEL-005**: 回归套件定期（每季度）进行冗余用例清理，移除覆盖重复的用例
- [ ] **RGT-SEL-006**: 冒烟测试子集从回归套件中抽取，执行时间 ≤ 5 分钟

### 2. 优先级分类检查 (5项)

- [ ] **RGT-PRI-001**: P0 用例覆盖所有核心业务路径（登录/注册/支付/核心流程），通过率 100%
- [ ] **RGT-PRI-002**: P1 用例覆盖重要功能的 Happy Path + 主要异常路径，通过率 ≥ 98%
- [ ] **RGT-PRI-003**: P2 用例覆盖边界条件、UI 细节、非关键功能，通过率 ≥ 95%
- [ ] **RGT-PRI-004**: 优先级定期（每迭代）由 PO + QA + Dev 三方确认，跟随业务变化调整
- [ ] **RGT-PRI-005**: P0/P1/P2 用例占比合理（15-20% / 40-50% / 30-40%）

### 3. 执行时间 SLA 检查 (5项)

- [ ] **RGT-SLA-001**: 全量回归测试执行时间 ≤ 30 分钟
- [ ] **RGT-SLA-002**: 冒烟测试执行时间 ≤ 5 分钟
- [ ] **RGT-SLA-003**: 回归用例支持并行执行（CI 节点数 ≥ 2），单组执行时间均衡
- [ ] **RGT-SLA-004**: 长时间执行的用例（> 2 min/条）有优化计划或拆分为更小用例
- [ ] **RGT-SLA-005**: 回归测试执行时间的周环比趋势无异常增长（增长率 ≤ 10%）

### 4. Flaky 率监控检查 (6项)

- [ ] **RGT-FLK-001**: Flaky 率 ≤ 3%（判断标准：10 次执行中结果不一致的用例比例）
- [ ] **RGT-FLK-002**: Flaky 测试有完整的标记和隔离机制，不阻塞 CI 流水线
- [ ] **RGT-FLK-003**: Flaky 测试在 48 小时内创建 Bug 并分配给责任人
- [ ] **RGT-FLK-004**: Flaky 测试的根因归类：环境依赖 / 数据竞态 / 时序依赖 / 外部服务不稳定
- [ ] **RGT-FLK-005**: Flaky 测试修复后在该功能模块运行至少 10 次确认稳定性
- [ ] **RGT-FLK-006**: 连续 3 次 Flaky 的用例自动降级至 P2 并通知 QA 负责人
