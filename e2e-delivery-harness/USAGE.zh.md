## 资产概述

### 资产类型

| 资产类型 | 用途 | 文件格式 |
|----------|------|----------|
| Agent | 定义 AI 角色身份和工作规则 | `*.agent.md` |
| Skill | 封装领域能力和操作步骤 | `skills/*/SKILL.md` |
| Instruction | 提供操作指南和检查清单 | `*.instructions.md` |
| Prompt | 指导 AI 生成规范输出 | `*.prompt.md` |
| Scenario | 组合资产形成业务流程 | `scenarios/*/SCENARIO.md` |
| Standard | 规范和检查标准 | `standards/*.md` |

## 使用流程

### 步骤 1：确定交付阶段

根据项目当前阶段选择对应的场景：

```
需求分析 → 系统设计 → 任务拆分 → 开发实现 → 测试验证 → 部署发布 → 监控运维
```

### 步骤 2：配置角色资产

1. 读取对应阶段的 **Agent** 定义文件
2. 了解角色的工具权限和工作规则
3. 根据项目需求调整角色配置

### 步骤 3：引用技能和指令

1. 在 Agent 的指导下加载对应 **Skill**
2. 遵循 **Instruction** 中的操作步骤
3. 参考 **Prompt** 模板构造输入

### 步骤 4：执行并产出

1. 按照技能定义执行具体任务
2. 参考指令中的检查清单进行自检
3. 输出符合规范的结果

### 步骤 5：质量评估

1. 使用 `evaluations/regression-checklist.md` 进行回归检查
2. 参考 `evaluations/scorecard-template.md` 进行评分
3. 如有问题，返回对应阶段进行修正

### 角色使用示例

```markdown
# 在 Agent 配置中引用角色

---
description: 负责需求分析与规划
tools: ["search", "edit", "analyze"]

1. 首先明确业务目标和约束
2. 识别干系人和用户需求
3. 输出结构化的需求规格
```

## 质量保障

### 检查清单

每个阶段完成后，执行以下检查：

1. **输入完整性**：是否包含所有必需的输入项
2. **输出规范性**：是否符合输出格式要求
3. **质量标准**：是否满足质量评估标准
4. **文档完整性**：是否包含必要的说明文档

### 评分体系

使用 1-5 分制进行质量评分：

- 5：优秀 - 完全满足所有标准
- 4：良好 - 基本满足，有小幅改进空间
- 3：合格 - 满足核心要求
- 2：需改进 - 存在明显不足
- 1：不合格 - 不满足基本要求

## 最佳实践

### 1. 渐进式使用

建议从单个阶段开始，逐步扩展到完整流程。

### 2. 上下文传递

每个阶段的输出应作为下一阶段的输入，确保信息连贯。

### 3. 迭代优化

根据实际使用反馈，持续优化资产定义。

### 4. 团队协作

多个 AI 角色协同时，应明确主从关系和交接规范。

## 常见问题

### Q: 如何选择合适的场景？
A: 根据项目当前阶段和目标，选择最匹配的阶段场景。

### Q: 角色配置可以修改吗？
A: 可以，但建议保留核心职责定义，仅调整工具权限和工作规则。

### Q: 如何贡献新资产？
A: 参考 `standards/authoring-checklist.md` 创建新资产，并通过评估后提交。
