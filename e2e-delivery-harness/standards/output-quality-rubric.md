# 产出质量评估标准

## Overview

本文件定义了 E2E Delivery Harness 体系中所有产出的质量评估标准和评分体系。适用于 AI Agent 生成结果（Prompt / Instruction / Agent / Skill / Scenario 等各类资产）以及人工编写文档的质量评审。采用六维度 0-10 分量表，每个维度设有明确的行为锚定（Behavioral Anchors），并支持综合加权评分。

## Six Scoring Dimensions（六维度评分标准）

每个维度独立评分，分数范围为 0-10（整数），通过行为锚定描述确保跨评估者的一致性。

| 维度 | 权重 | 维度代码 | 定义 |
|------|------|---------|------|
| **COMPLETENESS** 完整性 | 25% | `CMP` | 产出是否包含所有必需元素，无关键遗漏 |
| **STRUCTURE** 结构性 | 15% | `STR` | 产出结构是否清晰、层次合理、导航方便 |
| **TRACEABILITY** 可追溯性 | 20% | `TRC` | 产出是否可追溯到原始需求、决策依据、来源引用 |
| **QUANTIFIABLE** 可量化性 | 15% | `QNT` | 产出中的指标、约束、目标是否有明确量化定义 |
| **HANDOVER** 交接完备性 | 10% | `HOV` | 产出是否包含上下阶段交接所需的全部信息 |
| **ACTIONABLE** 可执行性 | 15% | `ACT` | 产出中的步骤、任务、建议是否可直接执行 |

### 1. COMPLETENESS（完整性）— 权重 25%

| 分数 | 等级 | 行为锚定描述 |
|------|------|-------------|
| **10** | 卓越 | 产出包含所有预期元素和扩展内容；所有边界情况已覆盖；无任何明显遗漏 |
| **7** | 良好 | 产出包含所有核心必需元素；次要边界情况基本覆盖；无关键遗漏 |
| **5** | 合格 | 产出包含主要必需元素；存在 1-2 项非关键遗漏；核心内容可用 |
| **3** | 不足 | 产出缺失 3 项以上必需元素；关键场景缺失；需要补充才能使用 |
| **0** | 不可用 | 产出严重不完整；核心内容缺失超过 50%；无法作为独立文档使用 |

### 2. STRUCTURE（结构性）— 权重 15%

| 分数 | 等级 | 行为锚定描述 |
|------|------|-------------|
| **10** | 卓越 | 结构层次清晰，逻辑递进完美；使用恰当的标题层级（H1→H2→H3）；导航目录完备；同一层级信息对等 |
| **7** | 良好 | 结构合理，核心层次分明；标题使用正确；少量段落位置可优化但不影响理解 |
| **5** | 合格 | 有基本结构框架；标题层级偶有跳跃；部分内容归类不够准确，但可读 |
| **3** | 不足 | 结构混乱；标题层级错误或多级跳跃；信息组织缺乏逻辑；需要重新组织 |
| **0** | 不可用 | 无结构化组织；纯段落堆砌；无标题或标题完全错误；完全无法导航 |

### 3. TRACEABILITY（可追溯性）— 权重 20%

| 分数 | 等级 | 行为锚定描述 |
|------|------|-------------|
| **10** | 卓越 | 每条需求/决策/设计均标注来源编号（REQ-*, DC-*）；引用外部文档链接有效；变更理由有据可查；双向追溯完整 |
| **7** | 良好 | 主要需求/决策标注了来源编号；外部引用基本有效；关键决策有理由说明；追溯链无明显断裂 |
| **5** | 合格 | 部分内容标注了来源；关键需求可追溯到原始输入；存在 1-2 处引用失效或编号缺失 |
| **3** | 不足 | 仅少数内容有追溯标记；多数决策无依据说明；外部引用大量缺失或失效 |
| **0** | 不可用 | 完全无追溯标记；所有需求/决策无来源依据；无法验证任何产出的来源 |

### 4. QUANTIFIABLE（可量化性）— 权重 15%

| 分数 | 等级 | 行为锚定描述 |
|------|------|-------------|
| **10** | 卓越 | 所有性能/质量/业务指标均量化（含阈值、单位、测量方法）；主观词汇完全消除 |
| **7** | 良好 | 核心指标有量化定义和阈值；少量次要描述使用主观词但影响有限 |
| **5** | 合格 | 主要指标有量化定义；存在 2-3 处使用「快速」「稳定」「友好」等主观词未量化 |
| **3** | 不足 | 关键指标未量化；多处使用主观词而无测量标准；无法基于产出进行客观验证 |
| **0** | 不可用 | 所有描述均为定性词汇；无一量化指标；完全无法衡量或验证 |

### 5. HANDOVER（交接完备性）— 权重 10%

| 分数 | 等级 | 行为锚定描述 |
|------|------|-------------|
| **10** | 卓越 | 完整包含前置依赖、输入物、输出物、验收标准、已知风险、待办事项；下一阶段可无缝衔接 |
| **7** | 良好 | 核心交接信息完备；存在 1-2 项非关键交接信息缺失但不影响下一阶段启动 |
| **5** | 合格 | 主要交接信息已提供；缺少依赖关系或风险说明但可通过上下文推断 |
| **3** | 不足 | 交接信息严重不足；缺少关键输入/输出定义；下一阶段需大量澄清 |
| **0** | 不可用 | 无任何交接信息；产出孤立无上下文；完全无法传递给下一阶段 |

### 6. ACTIONABLE（可执行性）— 权重 15%

| 分数 | 等级 | 行为锚定描述 |
|------|------|-------------|
| **10** | 卓越 | 每项任务/步骤有明确负责人、时间估计、验收条件；无歧义指令；可直接分配执行 |
| **7** | 良好 | 核心任务步骤清晰可执行；存在少量模糊描述但不影响整体执行 |
| **5** | 合格 | 主要步骤可执行；部分任务缺少时间估计或负责人；执行前需要少量澄清 |
| **3** | 不足 | 步骤描述模糊；大量任务缺少负责人、时间或验收条件；无法直接执行 |
| **0** | 不可用 | 所有步骤不可执行；指令含歧义、矛盾或缺失关键动作；完全无法落地 |

## Grade Classification（等级划分）

基于各维度加权总分，产出分为以下六个等级：

| 等级 | 综合评分范围 | 标签 | 含义 | 处理动作 |
|------|-------------|------|------|---------|
| **S** | 9.0 - 10.0 | 卓越 (Outstanding) | 远超预期，可作为标杆 | 发布 + 推荐为最佳实践 |
| **A** | 8.0 - 8.9 | 优秀 (Excellent) | 超过预期，少数可优化点 | 发布 + 记录优化建议 |
| **B+** | 7.0 - 7.9 | 良好 (Good) | 达到预期，有明确改进空间 | 发布 + 制定改进计划 |
| **B** | 6.0 - 6.9 | 达标 (Adequate) | 基本达标，需在下一迭代改进 | 有条件发布 + 设定改进期限 |
| **C** | 5.0 - 5.9 | 不足 (Below Average) | 不满足最低质量要求 | 退回修订 + 重新评审 |
| **D** | 0 - 4.9 | 不合格 (Unsatisfactory) | 严重不达标 | 退回重做 + 安排辅导 |

> **项目合格线**: 场景级产出要求综合评分 ≥ 7.0（B+ 级）方可通过质量门禁。
> **组织级标杆线**: 综合评分 ≥ 8.5（A- 级）方可作为全组织推荐资产。

## Composite Score Formula（加权综合评分公式）

### 计算公式

```
Composite Score = (CMP × 0.25) + (STR × 0.15) + (TRC × 0.20) + (QNT × 0.15) + (HOV × 0.10) + (ACT × 0.15)

其中：
  CMP = COMPLETENESS 维度得分 (0-10)
  STR = STRUCTURE     维度得分 (0-10)
  TRC = TRACEABILITY  维度得分 (0-10)
  QNT = QUANTIFIABLE  维度得分 (0-10)
  HOV = HANDOVER      维度得分 (0-10)
  ACT = ACTIONABLE    维度得分 (0-10)
```

### 评分计算示例

| 维度 | 得分 | 权重 | 加权得分 |
|------|------|------|---------|
| COMPLETENESS | 8 | 25% | 2.00 |
| STRUCTURE | 7 | 15% | 1.05 |
| TRACEABILITY | 6 | 20% | 1.20 |
| QUANTIFIABLE | 5 | 15% | 0.75 |
| HANDOVER | 7 | 10% | 0.70 |
| ACTIONABLE | 6 | 15% | 0.90 |
| **总分** | | | **6.60 (B 级)** |

### 维度致命缺陷规则

若任一维度得分低于 **3 分**，无论总分多少，该产出整体降一级处理。
若任意两个维度得分低于 **3 分**，产出直接判定为 **D 级（不合格）**。

### 等级确认算法

```
Algorithm: Grade Determination
Input: composite (0-10 float)
Output: grade (S/A/B+/B/C/D)

if any two dimensions < 3: return "D"
if any one dimension < 3: composite = min(composite, composite - 0.5)

if composite >= 9.0: return "S"
elif composite >= 8.0: return "A"
elif composite >= 7.0: return "B+"
elif composite >= 6.0: return "B"
elif composite >= 5.0: return "C"
else: return "D"
```

## Evaluator Calibration Guidelines（评估者校准指南）

### 评估者要求

- 每次评估须由至少 **2 位** 合格评估者独立完成
- 评估者须通过校准培训并获认证
- 评估者与被评估产出无直接利益关系

### 校准流程

```
1. 独立评分 → 2 位评估者各自独立完成六维度打分
2. 分数比较 → 逐维度比较评分差异
3. 差异讨论 → 对差异 > 2 分的维度进行讨论
4. 校准评分 → 达成共识后记录最终评分
5. 一致性统计 → 计算本次评估一致性比率
```

### 一致性要求

| 指标 | 目标 | 计算方法 |
|------|------|---------|
| 维度级一致性 | 80%（每个文件） | 差异 ≤ 2 分的维度数 / 6 × 100% |
| 评估者间一致性 | ≥ 80%（季度滚动） | 季度内一致性达标的评估次数 / 总评估次数 × 100% |
| 等级一致性 | ≥ 90%（季度滚动） | 两位评估者判定同一等级的比率 |

### 不一致处理

| 差异程度 | 处理方式 |
|---------|---------|
| 全部 6 维度差异 ≤ 1 分 | 取平均值作为最终分（四舍五入到整数） |
| 1-2 维度差异 2-3 分 | 讨论后重新评分；如仍不一致，引入第 3 位评估者仲裁 |
| 任一维度差异 ≥ 4 分 | 自动触发重新校准培训 + 第 3 位评估者仲裁 |
| 等级判定不一致（如 A vs B+） | 强制讨论直至达成一致，或引入仲裁 |

### 常见校准偏差 (Calibration Biases)

| 偏差类型 | 表现 | 纠正措施 |
|---------|------|---------|
| 光环效应 (Halo Effect) | 因某一维度高分而倾向在其他维度也给高分 | 强制按维度独立打分，完成后才展示总分 |
| 严格/宽松偏差 | 某评估者始终比其他评估者打低/高分 | 定期计算个人平均分与全局平均分的偏差 |
| 近期偏差 | 因最近阅读的类似产出而影响当前评分 | 每次评估前重读锚定描述，对照打分 |
| 居中趋势 | 避免打极端分数（全打 5 分附近） | 要求充分利用 0-10 全量表，标注极端案例 |

### 校准记录格式

每次评估须记录以下信息以供审计：

```yaml
evaluation:
  asset: "{资产名称}"
  asset_version: "{版本号}"
  evaluators:
    - name: "{评估者1}"
      scores: {CMP: 8, STR: 7, TRC: 6, QNT: 5, HOV: 7, ACT: 6}
    - name: "{评估者2}"
      scores: {CMP: 7, STR: 8, TRC: 6, QNT: 6, HOV: 7, ACT: 7}
  final:
    scores: {CMP: 8, STR: 7, TRC: 6, QNT: 5, HOV: 7, ACT: 6}
    composite: 6.60
    grade: "B"
    consensus: true
    calibration_note: "{讨论要点摘要}"
  date: "2026-06-23"
```

## Quality Improvement Guide

当评分低于预期时，按以下路径改进：

| 当前等级 | 目标等级 | 改进重点 |
|---------|---------|---------|
| D → C | C | 补齐基础内容缺失（COMPLETENESS 维度优先）；建立基本结构 |
| C → B | B | 加强追溯性（TRACEABILITY）和可量化性（QUANTIFIABLE）；完善交接信息 |
| B → B+ | B+ | 提升可执行性（ACTIONABLE）；消除主观词；增加量化指标 |
| B+ → A | A | 打磨结构层级（STRUCTURE）；补充边界情况和扩展内容 |
| A → S | S | 增加标杆级细节；补充自动化验证；完善全量追溯 |

## Compliance Checklist

- [ ] 所有 6 个维度已独立评分（COMPLETENESS / STRUCTURE / TRACEABILITY / QUANTIFIABLE / HANDOVER / ACTIONABLE）
- [ ] 每个维度评分参考了对应分数的行为锚定描述
- [ ] 综合加权评分已按公式计算
- [ ] 等级判定已考虑致命缺陷规则
- [ ] 至少 2 位评估者独立完成评分
- [ ] 评估者间一致性 ≥ 80%
- [ ] 校准记录已存档
- [ ] 维度差异 > 2 分的讨论原因已记录
- [ ] 评分结果已反馈给产出作者
- [ ] 低于 B+ 级的产出已制定改进计划
