# Lifecycle - 资产生命周期管理

## 概述

本文档定义了 E2E Delivery Harness 资产库中各类资产的完整生命周期管理流程。

## 生命周期阶段

```
┌─────────┐   ┌─────────┐   ┌─────────┐   ┌─────────┐   ┌─────────┐
│  Draft  │ → │  Review │ → │  Active │ → │  Update │ → │ Deprecated │
└─────────┘   └─────────┘   └─────────┘   └─────────┘   └─────────┘
```

## 阶段定义

### 1. Draft（草稿）

**定义**：资产初始创建阶段，尚未完成。

**准入条件**：
- 完成初步内容编写
- 包含基本元数据
- 通过格式检查

**退出条件**：
- 内容基本完整
- 通过同行评审
- 负责人审批通过

### 2. Review（评审）

**定义**：资产提交评审，等待审批。

**准入条件**：
- 符合命名规范
- 通过完整性检查
- 包含测试用例（如适用）

**退出条件**：
- 所有评审项通过
- 无阻塞性问题
- 获得至少 2 位评审者批准

### 3. Active（活跃）

**定义**：资产已发布，可正式使用。

**准入条件**：
- 完成评审流程
- 版本号分配
- 文档完善

**退出条件**：
- 发现重大问题需回退
- 被新版本替代
- 长期未维护

### 4. Update（更新）

**定义**：资产需要修订或增强。

**准入条件**：
- 发现改进空间
- 用户反馈建议
- 需求变更

**退出条件**：
- 变更完成并测试
- 版本号递增
- 重新评审通过

### 5. Deprecated（废弃）

**定义**：资产不再推荐使用。

**准入条件**：
- 被新资产替代
- 技术过时
- 使用率极低

**退出条件**：
- 完成迁移指南
- 通知所有使用者
- 保留存档

## 角色职责

| 角色 | 职责 |
|------|------|
| Author | 资产创建和维护 |
| Reviewer | 评审和反馈 |
| Approver | 最终审批 |
| Curator | 整体管理和协调 |

## 版本管理

### 版本号规范

```
主版本.次版本.修订号

例如：1.0.0
- 主版本：重大变更，不兼容
- 次版本：新增功能，向后兼容
- 修订号：问题修复，向后兼容
```

### 变更记录

每次版本更新需记录：

| 字段 | 描述 |
|------|------|
| version | 版本号 |
| date | 变更日期 |
| author | 变更作者 |
| type | 变更类型 |
| description | 变更描述 |
| breaking | 是否破坏性变更 |

## 质量门禁

### Draft → Review

- [ ] 格式规范检查通过
- [ ] 元数据完整
- [ ] 基本内容完整

### Review → Active

- [ ] 技术评审通过
- [ ] 实用性评审通过
- [ ] 文档评审通过
- [ ] 至少 2 人批准

### Active → Update

- [ ] 变更申请记录
- [ ] 影响评估完成
- [ ] 回归测试计划

## 发布流程

```
1. 完成资产编写
2. 提交评审申请
3. 执行评审流程
4. 修复评审问题
5. 获得批准
6. 分配版本号
7. 更新资产状态
8. 通知使用者
```

## 回退流程

```
1. 发现重大问题
2. 评估影响范围
3. 决策回退方案
4. 执行回退操作
5. 通知相关方
6. 启动修复流程
```
