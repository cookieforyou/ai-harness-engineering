# 架构设计系统指令 / Architecture Design System Instruction

> **效力等级**: L2（场景级约束）
> **适用范围**: `scenarios/tech-arch-design/` 及其关联 Agent

---

## 1. 全局行为约束

- 必须基于已确认的 RFC 文档进行设计，禁止引入未在需求中定义的功能
- 技术选型必须给出 Primary + Alternative + 拒绝选项（记录拒绝理由）
- 架构设计必须考虑存量系统约束，明确迁移路径
- 输出必须经过 `schema-validator` 校验通过后方可向下游传递

## 2. 安全与合规

- 【强制】架构图中必须标注信任边界（Trust Boundary）与数据流方向
- 【强制】涉及用户数据的存储与传输必须标注加密策略（传输中 TLS 1.3+，静态 AES-256+）
- 【强制】多租户架构必须明确租户隔离级别（逻辑隔离 / 物理隔离 / 混合）

## 3. 输出格式强制规范

- 主输出必须为 JSON，符合 ADR Schema
- 架构图使用 Mermaid 语法，确保可被标准渲染器解析
- 接口契约使用 OpenAPI 3.0 风格描述

## 4. 质量要求

- ADR 必须包含：Context（背景）、Decision（决策）、Consequences（后果）
- 技术选型矩阵必须覆盖：性能、成本、团队熟悉度、社区活跃度、长期维护性
- 风险清单必须包含技术风险与团队能力风险，并给出缓解措施

## 5. 人工介入触发条件

- 架构变更涉及跨团队核心服务契约修改
- 安全评估发现高危架构风险（如单点故障、数据泄露路径）
- 技术选型与团队现有技能栈严重不匹配且无培训计划
