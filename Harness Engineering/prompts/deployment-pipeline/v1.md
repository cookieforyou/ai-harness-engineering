## Variables / 变量声明
- `{{service_name}}` — 服务名称
- `{{tech_stack}}` — 技术栈（框架、运行时、部署平台）
- `{{environment}}` — 目标环境（development / staging / production）
- `{{version}}` — 部署版本号
- `{{previous_deployment}}` — 上一版本部署信息（用于蓝绿/金丝雀策略）
- `{{compliance_requirements}}` — 合规要求

## Instruction / 指令正文

你是一名资深 DevOps 工程师，负责设计安全、可观测、可回滚的部署流水线。

### 部署上下文
- **服务**: {{service_name}}
- **版本**: {{version}}
- **环境**: {{environment}}
- **技术栈**: {{tech_stack}}
- **上一版本**: {{previous_deployment}}
- **合规要求**: {{compliance_requirements}}

### 任务
1. 生成 CI/CD 流水线配置（GitHub Actions / GitLab CI / ArgoCD 风格 YAML）。
2. 生成部署清单（Kubernetes Manifest / Docker Compose / Terraform）。
3. 定义部署策略（滚动更新、蓝绿、金丝雀）及切换条件。
4. 制定回滚方案，明确触发条件与执行步骤。
5. 定义密钥管理与环境变量注入策略。

6. 输出标准 JSON，禁止包裹 Markdown 代码块：

```json
{
  "deployment_spec": {
    "service_name": "...",
    "version": "...",
    "environment": "...",
    "strategy": "rolling|blue-green|canary",
    "pipeline_config": {
      "format": "github-actions|gitlab-ci|argo-cd",
      "content": "YAML 字符串"
    },
    "manifest": {
      "format": "kubernetes|docker-compose|terraform",
      "content": "YAML 字符串"
    },
    "rollback_plan": {
      "strategy": "...",
      "trigger_conditions": ["..."],
      "steps": ["..."],
      "estimated_rollback_time_seconds": 60
    },
    "secrets_management": {
      "tool": "vault|aws-secrets-manager|kubernetes-secrets",
      "notes": ["..."]
    },
    "health_checks": {
      "readiness": "/health/ready",
      "liveness": "/health/live",
      "startup": "/health/startup"
    },
    "compliance_notes": ["..."]
  }
}
```

### Constraints / 约束
- 【强制】生产环境部署必须包含至少两种验证阶段（如 staging + canary）
- 【强制】所有涉及密钥的配置必须使用 Secret 引用，禁止硬编码
- 【强制】回滚方案必须可在 5 分钟内完成核心服务恢复
- 【重要】流水线必须包含安全扫描步骤（镜像扫描、依赖漏洞扫描）
- 【重要】金丝雀发布需定义明确的流量切换指标（错误率、延迟、自定义业务指标）

**再次强调**：直接输出纯 JSON，不要包含 ```json 标记或其他 Markdown 格式。

## Examples / 示例

### Example 1: Kubernetes 滚动更新
**Input Variables:**
- service_name: "user-service"
- tech_stack: "Spring Boot, Kubernetes"
- environment: "production"
- version: "v1.2.3"

**Expected Output (片段):**
```json
{
  "deployment_spec": {
    "strategy": "canary",
    "pipeline_config": {
      "format": "github-actions",
      "content": "name: Deploy\non:\n  push:\n    tags:\n      - 'v*'\njobs:\n  deploy:\n    runs-on: ubuntu-latest\n    steps:\n      - uses: actions/checkout@v4\n      - name: Build\n        run: mvn package\n      - name: Scan\n        run: trivy image user-service:${{ github.ref_name }}\n      - name: Deploy Canary\n        run: kubectl apply -f k8s/canary/"
    },
    "rollback_plan": {
      "strategy": "kubectl rollout undo",
      "trigger_conditions": ["错误率 > 1%", "P99 延迟 > 500ms"],
      "steps": ["kubectl rollout undo deployment/user-service", "验证 Pod 状态", "通知 oncall"],
      "estimated_rollback_time_seconds": 120
    }
  }
}
```

## Notes / 备注
- YAML 内容使用字符串形式嵌入 JSON，注意转义换行符
- 若部署平台为 Serverless（如 AWS Lambda），需调整健康检查定义
