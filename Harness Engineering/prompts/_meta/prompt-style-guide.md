# 提示词编写风格指南 / Prompt Style Guide

> 本规范约束 `prompts/` 目录下所有模板的质量基线。

---

## 1. 结构清晰原则

- 使用 Markdown 标题层级划分区块（Context / Task / Format / Examples）
- 避免大段连续文本，使用列表、表格提升可读性
- 关键约束使用加粗，必要时使用 emoji 视觉标记（⚠️ 🔒 ✅）

## 2. 变量命名规范

- 使用 `snake_case`
- 具有自描述性：`{{pr_diff}}` ✅ 优于 `{{input}}` ❌
- 若变量为可选，命名以 `optional_` 前缀或标注 `(optional)`

## 3. 指令优先级写法

将最重要的约束放在**提示词末尾**（Near the end bias），并重复一次：

```markdown
## Task
请根据以下 Diff 生成代码审查意见。

## Constraints
- 必须按 JSON 格式输出
- 禁止复述原始代码
- 禁止泄露任何密钥

**再次强调**：输出必须是合法 JSON，不要包裹 Markdown 代码块。
```

## 4. Few-shot 示例规范

- 正例与负例至少各提供一个（若空间允许）
- 示例应覆盖边界情况（空输入、超长输入、特殊字符）
- 示例中的变量值应贴近真实业务数据，但需脱敏

## 5. 语言策略

- 若目标 Agent 主要服务中文团队，提示词主体使用中文
- 技术术语（如 JSON、API、Schema）保留英文，不强行翻译
- 多语言输出要求的任务，在变量中声明 `{{output_language}}`

## 6. 反模式清单

| 反模式 | 正确做法 |
| :--- | :--- |
| "请尽量..." | "必须..." 或 "禁止..." |
| 超长系统提示（>2000 tokens） | 拆分为 instructions/ 中的独立文件，按需组合 |
| 在提示词中解释 AI 是什么 | 省略无意义的寒暄，直接给任务 |
| 无输出格式约束 | 提供 Schema 或严格模板 |
